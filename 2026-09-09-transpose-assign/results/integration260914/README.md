**Date**: 2026-09-14. Base: `origin/master` = `c08e44a` (PR #101 squash:
elementwise blocked 2-D iteration; master already carries PR #100 argmax +
nanarg). Patch applied as working tree on branch `260914-transpose`

## Protocol

Same-session paired criterion passes, matching the patch-1/2 integration
cycles: `refA` = clean master, `cand` = patched tree, alternating within each
pass, 3 passes × {portable, native}. Full `--bench transpose` suite (56
benchmarks per stage) per stage; `RAYON_NUM_THREADS=16`; no other load on the
machine. Stages: `paired_bench.sh` (idempotent, resume-marker per stage,
state-aware tree flips); logs `*.log`; tables generated by `make_table.py`
from the criterion point estimates only (its `change:` lines are meaningless
under alternating trees). Binary-identity guard per T8's RUSTFLAGS-caching
lesson: md5 of the newest bench binary logged after every stage
(`binary_md5.txt`) — two distinct md5s per config (refA vs cand), stable
across passes; no stale-binary anomaly.

## Fall-through canaries (the cells that must not move)

All 12 `assign_gates` cells (contig small/large, sliced + sliced_t
large/odd, serial + faer16) stay at parity: serial cells 1.00–1.01×, faer16
cells 0.99–1.04×, with one borderline cell dissected below. The
`sliced_*` cells exercise the guard-rejection path (fast-axis stride 2 →
blocked kernel must be rejected → generic iterator path), and `contig_*`
never reaches the guarded branch — both behave as if the patch were absent,
as designed.

### Dissection: `sliced_t_large_2048x2048-faer16-f64/assign` (native)

The only cell whose 3-pass ratio range touched the flag threshold
(1.05–1.08×; refA 819–826 µs vs cand 866–890 µs). Targeted re-dissection
(`dissect_slicedt.sh`, 3 alternating single-bench refA/cand runs, native):

| run | refA | cand |
|---|---|---|
| 1 | 865 µs | 835 µs |
| 2 | 834 µs | 958 µs |
| 3 | 912 µs | 857 µs |

Within-tag spread (refA 834–912, cand 835–958) is as large as the between-tag
gap and the sign flips across alternations → **not a stable regression**;
sub-ms faer cells carry ±5–8% transients (same lesson as the phase-2
dissection of this very cell, and T3's re-run-3× rule). The guard provably
never fires here (fast-axis stride 2 ≠ 1), so no mechanism exists; the
paired-suite delta was refA drawing an unusually fast triplet. The portable
counterpart of the same cell is 0.87–1.00× (cand faster) — opposite sign,
same untouched code path.

## Notes / deviations from the patch-2 protocol

- Tree flip is `git apply` / `git apply -R` of the patch file instead of
  `git stash` push/pop: the rstsr repo carries a pre-existing user stash
  (`stash@{0}` from `enhance-core-tests-0.7.9`) that must not be entangled.
  Flips are state-aware (no-ops when already in the target state) and every
  flip asserts the resulting tree state.
- `refA_portable_pass1.log` is from the first (aborted) launch — the script's
  completion marker was wrong (`_f64` vs the actual `-f64` in criterion ids),
  the suite itself had completed all 56 benches, and the corrected script
  reused that log. Same session, same protocol, machine otherwise idle.
- `cargo fmt -p rstsr-native-impl` after benching: zero drift inside the 4
  patch files (phase-2 captured the patch post-fmt); the only changes were
  comment re-wraps of pre-existing master code in `cpu_{rayon,serial}/
  reduction.rs` (local rustfmt vs CI nightly wrapping — the patch-1 CI
  lesson), reverted as out of scope. After reverting, `git diff` of the tree
  is byte-identical to `proposed.patch` — no separate post-fmt capture needed.
