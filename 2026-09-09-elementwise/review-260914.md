## Theoretical soundness (checked, holds)

1. **Broadcast guard is exact, not heuristic.** `translate_to_col_major`
   asserts all layouts share one shape (`rstsr-common/src/layout/rearrangement.rs`),
   and upstream broadcast materializes broadcast axes as full-shape/stride-0
   (`update_layout_by_shape`). So "broadcast axis" is precisely `d > 1 && s == 0`
   — what the guard rejects, on all participating layouts. Shape-1 axes are
   harmless (loop bounds come from the shared shape). The guard is only a path
   selector: over-rejection costs perf, never correctness.
2. **Address arithmetic is the canonical formula.** `offset + Σ idx·stride`
   accumulated in `isize`, `usize` cast at the addressing site — identical to
   `IterLayoutColMajor`. No intermediate can overflow for a valid layout (each
   partial sum is the offset of a real in-bounds element). Offsets re-anchored
   per tile row → no drift.
3. **Exact coverage, write-once.** Tiles partition the 2-D index space; in the
   rayon kernels, slow-axis bands partition the output → disjoint writes; `c`
   is type-level disjoint from inputs.
4. **Bounds** match the file's established raw-pointer contract
   (`debug_assert` per element); serial path uses slice indexing (panics, no
   UB in release).

## Findings and dispositions

1. **Tall-skinny parallel degree (perf, medium) — documented, not fixed.**
   The rayon path parallelizes over slow-axis tile bands only
   (`ceil(dim_slow/64)` tasks); 70×10000 gives 2 bands and measured ~1.5×
   slower than the old outer-parallel path on 8 threads. Fix sketch if ever
   wanted: flatten `(t_slow, t_fast)` into one `par_iter` over
   `n_tiles_slow × n_tiles_fast` (tiles are write-disjoint, so sound).
   Disposition: added a caveat paragraph to the `blocked_2d_applicable_rayon`
   doc comment (in the rstsr working tree).
2. **Serial visit order changes for stateful closures (behavioral, low).**
   For ≥4096-element qualifying problems the serial kernel visits in tiled
   order, not strict col-major. Bit-identical for stateless ops (everything
   rstsr ships); a *stateful* user `FnMut` (per-element RNG, external
   accumulator/counter) observes a different sequence — per-element RNG also
   changes the buffer contents. Aliased in-place (`c += c.t()`) is unreachable
   through the safe API (borrow rules: one `&mut` + one shared of the same
   storage cannot coexist). Disposition: already documented in the kernel doc
   comments ("Visit order" sections).
3. **Nits.** (a) Unneeded `#[allow(clippy::too_many_arguments)]` on
   `blocked_2d_2layouts_cpu_rayon` (6 args) — removed. (b) `TILE`/`TILE_SWITCH`
   + guard duplicated across the serial/rayon files — left as-is; consistent
   with the pre-existing `CONTIG_SWITCH` duplication, and a third copy would
   be the time to hoist. (c) Scalar-operand kernels (`*_numb_*`/`*_numa_*`)
   still take the generic path for strided 2-D (`2.0 * b.t()` stays slow) —
   reasonable follow-up, not a defect.
