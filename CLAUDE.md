# rstsr-improve-trajectory

Scratch repository tracking the **trajectory of improving rstsr's efficiency**.
This is an R&D playground, not a product: free-form, fully AI-agent-driven
(human gives tasks and guidance via prompts), and deliberately not bound by
the software-development conventions of the main rstsr repos.

Everything here is a suggestion unless marked **mandatory**. Expect the rules
to evolve; keep wording loose and leave room for future directions.

## What this repo is for

- Try efficiency improvements that are impossible or inconvenient inside the
  crates intended for publication (benchmark harnesses, experimental kernels,
  vendor-and-patch experiments, etc.).
- Record how rstsr's efficiency was improved over time: every experiment, its
  numbers, and its outcome live **here**, not in the main rstsr repo.
- Efficiency means primarily runtime performance, but not limited to it —
  compile time, memory footprint, and similar aspects count when relevant.

## Structure

- One directory per experiment at repo root, named `YYYY-MM-DD-<task>`
  (kebab-case task slug), e.g. `2026-09-08-bench-core-ops`.
- Each directory is **self-contained and unrelated to other directories**:
  it carries complete code and represents rstsr *as of that date*. Directories
  are not required to be compatible with each other — rstsr's source may have
  changed between them. Any linkage to rstsr source is acceptable (pinned
  dependency, vendored copy, local path — whatever works for the task).
- There is no task tracker and no fixed task assignment. Tasks are given
  ad-hoc by the human.
- Each directory ideally has a README recording: the rstsr commit it was made
  against, environment (CPU/toolchain/flags/threads/device), baseline numbers,
  post-change numbers, and a conclusion. Skipping parts is tolerated when the
  experiment doesn't need them; a bare directory with no explanation is not.

## Benchmarks

- No fixed standard. A soft default is `criterion` (already declared in the
  rstsr workspace). Deviate freely; note the choice in the directory README.
- Toolchain/device matrix is open per directory: CPU serial, rayon, SIMD
  (AVX-512 etc.), CUDA/HIP, whatever the task calls for.
- A stricter standard may be proposed in the future; nothing here is frozen.

## Results and handoff

- All benchmark outputs and reports stay inside this repository's task
  directories. The main rstsr repo receives reports only inside PRs, and PRs
  are opened **only with explicit user permission**.
- When an experiment proves a win, its directory records the patch (diff) plus
  porting notes; the human integrates it into rstsr under rstsr's normal
  review policy. Do not push changes into the main repos from here.

## Agent memory (mandatory convention)

Agent memory lives **inside this repository**, at `.claude/memory/`:

- `.claude/memory/MEMORY.md` is the index; one line per memory file.
- Memory files are plain markdown with frontmatter (`name`, `description`,
  `metadata: type: user | feedback | project | reference`), one fact per file.
- At session start, read `.claude/memory/MEMORY.md` (and files relevant to the
  task). During/after work, write durable learnings (machine facts, rstsr
  quirks, benchmark pitfalls, user preferences) as new memory files and add
  them to the index. Machine-level memory outside the repo may also be used,
  but the in-repo memory is the canonical, committed record.

## Git

- The agent **may commit autonomously in this repository** (this repo is
  designed to be virtually fully AI-generated). The no-auto-commit policy of
  the main rstsr repos does not apply here.
- **Mandatory**: follow the `git-commit-coauthor` skill
  (`.claude/skills/git-commit-coauthor/`) for commit trailers. Subject lines
  are free-form; suggested shape `<task-dir>: <summary>`.
- Commit `Cargo.lock` (benchmark reproducibility); `.gitignore` already
  handles this.
- "Generated by AI" attribution notices are **not required** in this
  repository; the co-author trailers in commits are sufficient.

## Isolation

This repository is standalone. The surrounding workspace (`rstsr_pack`) does
not reference it, and agent memory of other projects must not mention it.
When working in the main rstsr repos, treat this repo as unrelated.
